# 02-三大框架比較

## 一、前端框架與三大框架比較

### 1-1 何謂前端框架？

**前端框架（Front-end Framework）** 是一套預先設計好的程式架構與工具集，協助開發者用「一致的方式」建構網頁應用（特別是 SPA，單頁應用）。

原生 JS 需要自己做這些事：

- 手動操作 DOM（找元素、改內容、綁事件）
- 手動讓「資料」與「畫面」同步
- 自己決定程式碼如何分檔、分層

框架幫你處理：

| 框架提供的能力 | 說明                                                           |
| -------------- | -------------------------------------------------------------- |
| 資料驅動畫面   | 資料變了，畫面自動更新（響應式 / 狀態管理），不必手動 DOM 操作 |
| 元件化         | 把畫面切成可重複使用的元件（UI + 邏輯 + 樣式封裝）             |
| 模板 / JSX     | 以宣告式語法描述畫面                                           |
| 路由           | 前端換頁不重新載入（Vue Router、React Router、Angular Router） |
| 狀態管理       | 跨元件共享資料（Pinia、Redux / Zustand、NgRx / Signals）       |
| 工程化         | 搭配打包工具（Vite、Webpack）、TypeScript、測試與熱更新        |

> **Library vs Framework**：嚴格來說 React 自稱「函式庫」（只管 UI 層），Angular 是「完整框架」（全包），Vue 號稱「漸進式框架」（核心只管畫面，路由與狀態再按需加入）。日常口語中三者都被稱為「前端框架」。

**為什麼需要框架？** 當頁面互動變多（表單、清單、即時更新），原生 DOM 操作會變得難以維護；框架用「宣告式」取代「命令式」，讓開發者專注在資料與業務邏輯。

### 1-2 三大框架的源起與發展

#### Angular

| 年份    | 事件                                                                                 |
| ------- | ------------------------------------------------------------------------------------ |
| 2010    | Google 發布 **AngularJS**（1.x），提出雙向綁定、MVC、依賴注入                        |
| 2016    | **Angular 2** 發布，**完全重寫**，改用 TypeScript、元件化，與 AngularJS 不相容       |
| 2016 後 | 改為語意化版本、每半年一個大版本（Angular 4 起，跳過 3）                             |
| 2022~   | Standalone Components（可不再需要 NgModule）                                         |
| 2023~   | Angular 16 起導入 **Signals** 響應式；17 起新內建控制流程（`@if`、`@for`）與全新品牌 |
| 2022    | AngularJS 停止支援（2021-12 EOL）                                                    |

- 由 **Google** 主導，企業級定位。
- 痛點：AngularJS → Angular 2 的斷層讓許多團隊流失，也使「Angular 學習曲線陡峭」的印象深植。

#### React

| 年份 | 事件                                                                          |
| ---- | ----------------------------------------------------------------------------- |
| 2011 | Facebook 工程師 **Jordan Walke** 在內部（動態消息）開始使用                   |
| 2013 | 在 JSConf US 開源，提出 **Virtual DOM**、JSX；起初備受質疑（HTML 寫在 JS 裡） |
| 2015 | React Native 發布（用 React 寫行動 App）                                      |
| 2019 | React 16.8 推出 **Hooks**（`useState`、`useEffect`），函式元件成為主流        |
| 2022 | React 18：Concurrent 渲染、自動批次更新                                       |
| 2024 | React 19：Actions、`use`、Server Components 穩定，並搭配 Next.js 等框架       |

- 由 **Meta（Facebook）** 與社群共同維護。
- 生態系最龐大，但需要自行選擇路由、狀態管理、資料請求等方案（較自由，也較分裂）。

#### Vue

| 年份      | 事件                                                                                                             |
| --------- | ---------------------------------------------------------------------------------------------------------------- |
| 2013~2014 | 前 Google 工程師 **尤雨溪（Evan You）** 在使用 AngularJS 後，想抽出其中最輕巧的部分，個人開發出 Vue，2014 年公開 |
| 2016      | Vue 2：引入 Virtual DOM、更完整的生態（Vue Router、Vuex）                                                        |
| 2020      | **Vue 3**：Composition API、Proxy 響應式、更好的 TypeScript 支援、更小更快                                       |
| 2022      | Vue 3 成為預設版本；Pinia 取代 Vuex 成為官方狀態管理；Vite（同樣由尤雨溪創作）成為標準工具                       |
| 2023      | Vue 2 結束支援（2023-12-31）                                                                                     |
| 近年      | Vue 3.5 響應式系統優化；Vapor Mode 實驗（無虛擬 DOM 編譯模式）                                                   |

- 起初為**個人專案**，由社群捐助與贊助維護，並非大公司主導，但在亞洲（中國、台灣、日本）採用率特別高。
- 定位「**漸進式框架**」：可以只用 CDN 引入，也可以用 Vite + SFC 做大型專案。

### 1-3 三大框架特色比較

| 比較項目      | **Vue 3**                                           | **React 19**                              | **Angular（現行版）**                     |
| ------------- | --------------------------------------------------- | ----------------------------------------- | ----------------------------------------- |
| 發布者        | 尤雨溪 / 社群                                       | Meta / 社群                               | Google                                    |
| 定位          | 漸進式框架                                          | UI 函式庫                                 | 完整的企業級框架                          |
| 語言          | JS / TS（皆可）                                     | JS / TS（JSX / TSX）                      | **TypeScript（必備）**                    |
| 畫面描述      | **HTML 模板** + 指令（`v-if`、`v-for`）             | **JSX**（JS 中寫 HTML）                   | HTML 模板 + `@if` / `@for` 控制流程       |
| 資料流        | 雙向綁定（`v-model`）+ 單向 props                   | 嚴格**單向**資料流                        | 雙向綁定（`[(ngModel)]`）+ 單向 inputs    |
| 響應式機制    | Proxy 自動追蹤依賴（`ref` / `reactive`）            | 需手動 `setState`，以重新渲染 + diff 為主 | Signals（新）、Zone.js 變更偵測（舊）     |
| 元件寫法      | Options API / Composition API、單檔元件 SFC         | 函式元件 + Hooks                          | 類別元件 + 裝飾器（`@Component`）         |
| 內建功能      | 核心小；路由（Vue Router）、狀態（Pinia）為官方套件 | 核心只管 UI，路由 / 狀態靠社群            | **全包**：路由、表單、HTTP、DI、測試、CLI |
| 學習曲線      | **平緩**                                            | 中等（需懂 JSX、Hooks 規則）              | **陡峭**（TS、DI、RxJS、模組概念）        |
| 靈活度        | 中高                                                | **最高**（自由組合）                      | 低（規範嚴格，團隊風格一致）              |
| 打包大小      | 小（約 30~40 KB gzip）                              | 小～中（約 40~45 KB）                     | 較大                                      |
| 官方工具      | Vite、Vue DevTools、create-vue                      | Vite / Next.js、React DevTools            | Angular CLI                               |
| 周邊框架      | Nuxt                                                | Next.js、Remix                            | Angular Universal（SSR）                  |
| 行動 / 跨平台 | Capacitor、Quasar、uni-app                          | **React Native**                          | Ionic                                     |

#### 各自的優缺點

**Vue**

- 優：上手最快、文件友善（中文資源豐富）、模板直覺、響應式不需手動通知、官方套件完整。
- 缺：生態與就業機會略少於 React；彈性高但寫法選擇多（Options / Composition）造成風格不一；歐美大型企業採用相對較少。

**React**

- 優：生態最大、職缺最多、跨平台（React Native）、彈性最高、社群資源豐富。
- 缺：只是 UI 層，要自己組合工具鏈；JSX 與 Hooks（閉包陷阱、依賴陣列）有學習門檻；更新頻繁，寫法演進快。

**Angular**

- 優：功能完整、內建規範、TypeScript 型別安全、適合大型團隊與長期維護。
- 缺：學習曲線陡、樣板碼（boilerplate）多、體積較大、小專案顯得笨重。

---

### 1-4 三大框架的應用場景

| 框架        | 適合場景                                                             | 代表使用者                                                                     |
| ----------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **Vue**     | 中小型專案、快速開發、後台管理系統、既有網站逐步導入、教學與新手入門 | Alibaba、小米、GitLab、Nintendo、台灣許多中小企業與新創                        |
| **React**   | 大型互動式網站、社群 / 內容平台、需 SSR / SEO（Next.js）、跨行動端   | Facebook、Instagram、Netflix、Airbnb、Uber                                     |
| **Angular** | 大型企業系統、金融 / 政府 / ERP、多人長期維護、需要嚴格規範的專案    | Google（部分產品）、Microsoft Office 網頁部分、Deutsche Bank、各種企業內部系統 |

#### 選擇建議

- **新手、小團隊、想快速做出成品** → Vue
- **想要最多職缺、最大生態系、可能做 App** → React
- **大型企業、多人協作、需要強規範與型別安全** → Angular

> 沒有「最好」的框架，只有「最適合」的。三者核心觀念（元件化、響應式 / 狀態驅動、單向資料流、路由、狀態管理）相通，學會其中一個，轉換成本不高。

## 二、從原生 JS 逐步轉成三大框架

以下以兩個範例說明：

1. `getProducts.html`：呼叫 API 並渲染清單（**非同步資料 + 清單渲染**）
2. `todolist.html`：新增 / 刪除待辦（**表單輸入 + 清單 + 事件**）

> 關於 todolist 從 JS 轉 Vue 的詳細步驟，也可參考 [將todolist從JS轉到Vue.md](將todolist從JS轉到Vue.md)。

---

### 2-1 範例一：getProducts（串接 API 取得產品資料）

#### ① 原生 JS（原始碼）

```html
<ul id="list"></ul>
<script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script>
<script>
  const api_path = "kentlee406";
  axios
    .get(
      `https://livejs-api.hexschool.io/api/livejs/v1/customer/${api_path}/products`,
    )
    .then((response) => {
      const list = document.getElementById("list");
      response.data.products.forEach((product) => {
        const li = document.createElement("li");
        li.textContent = product.title;
        list.appendChild(li);
      });
    })
    .catch((error) => console.error(error));
</script>
```

**特徵**：取得資料後，自己 `createElement` → 設定內容 → `appendChild`。

#### ② 轉成 Vue 3（逐步）

**步驟一：建立環境**——載入 Vue 與 axios 的 CDN，準備 `#app` 掛載點，建立空的 Vue 應用。

```html
<!-- Vue 要接管的區域 -->
<div id="app"></div>

<!-- 載入 Vue 3 與 axios（CDN） -->
<script src="https://unpkg.com/vue@3.5.13/dist/vue.global.prod.js"></script>
<script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script>
<script>
  // 建立 Vue 應用，並掛載到 #app
  Vue.createApp({}).mount("#app");
</script>
```

**步驟二：建立 `data`**——原生 JS 沒有「狀態」，資料取回後直接操作 DOM；Vue 要先宣告資料放哪裡。

```html
<div id="app"></div>
<script src="https://unpkg.com/vue@3.5.13/dist/vue.global.prod.js"></script>
<script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script>
<script>
  Vue.createApp({
    // data：存放這個應用的「狀態」，資料變了畫面會自動更新
    data() {
      return {
        apiPath: "kentlee406", // 對應原本的 api_path
        products: [], // 產品清單，一開始是空陣列，等 API 回傳後再填入
      };
    },
  }).mount("#app");
</script>
```

**步驟三：撰寫模板**——用 `v-for` 取代原本的 `createElement` + `appendChild`。

```html
<div id="app">
  <ul>
    <!-- v-for：products 有幾筆就產生幾個 li -->
    <!-- :key：給每個項目唯一識別，讓 Vue 能正確比對更新 -->
    <!-- {{ }}：插值，顯示產品名稱（取代 li.textContent） -->
    <li v-for="product in products" :key="product.id">{{ product.title }}</li>
  </ul>
</div>
<script src="https://unpkg.com/vue@3.5.13/dist/vue.global.prod.js"></script>
<script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script>
<script>
  Vue.createApp({
    data() {
      return {
        apiPath: "kentlee406",
        products: [],
      };
    },
  }).mount("#app");
</script>
```

**步驟四：在 `mounted()` 取得資料**——掛載完成後呼叫 API，只要把結果指派給 `products`，畫面就會自動更新。

```html
<div id="app">
  <ul>
    <li v-for="product in products" :key="product.id">{{ product.title }}</li>
  </ul>
</div>
<script src="https://unpkg.com/vue@3.5.13/dist/vue.global.prod.js"></script>
<script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script>
<script>
  Vue.createApp({
    data() {
      return {
        apiPath: "kentlee406",
        products: [],
      };
    },
    // mounted：生命週期鉤子，畫面掛載完成後自動執行（適合發送初始請求）
    mounted() {
      axios
        .get(
          // 在選項式 API 中，用 this 取得 data 內的資料
          `https://livejs-api.hexschool.io/api/livejs/v1/customer/${this.apiPath}/products`,
        )
        .then((res) => {
          // 只要改資料，Vue 就會自動重新渲染，不需手動操作 DOM
          this.products = res.data.products;
        })
        .catch((error) => {
          console.error(error);
        });
    },
  }).mount("#app");
</script>
```

#### ③ 轉成 React（逐步）

**步驟一：建立環境**——React 的 CDN 版需搭配 Babel 才能寫 JSX（正式專案建議用 Vite）。

```html
<!-- React 要接管的區域 -->
<div id="root"></div>

<!-- React 19 已不提供 UMD 版，CDN 教學請用 18 -->
<script src="https://unpkg.com/react@18/umd/react.production.min.js"></script>
<script src="https://unpkg.com/react-dom@18/umd/react-dom.production.min.js"></script>
<!-- Babel：讓瀏覽器看得懂 JSX -->
<script src="https://unpkg.com/@babel/standalone/babel.min.js"></script>
<script src="https://cdn.jsdelivr.net/npm/axios/dist/axios.min.js"></script>

<!-- type="text/babel"：交給 Babel 轉譯 -->
<script type="text/babel">
  // React 的元件就是一個「回傳畫面的函式」，名稱需大寫開頭
  function App() {
    return <ul></ul>;
  }

  // 建立根節點並渲染 App 元件（相當於 Vue 的 mount）
  ReactDOM.createRoot(document.getElementById("root")).render(<App />);
</script>
```

**步驟二：用 `useState` 建立狀態**——相當於 Vue 的 `data`。

```html
<script type="text/babel">
  // 從 React 取出 Hook
  const { useState } = React;
  const apiPath = "kentlee406";

  function App() {
    // useState([])：回傳 [目前的值, 修改值的函式]
    // products 是只讀的；要更新必須呼叫 setProducts
    const [products, setProducts] = useState([]);

    return <ul></ul>;
  }

  ReactDOM.createRoot(document.getElementById("root")).render(<App />);
</script>
```

**步驟三：用 `map` 撰寫 JSX**——相當於 Vue 的 `v-for`。

```html
<script type="text/babel">
  const { useState } = React;
  const apiPath = "kentlee406";

  function App() {
    const [products, setProducts] = useState([]);

    return (
      <ul>
        {/* JSX 中用 { } 嵌入 JS 運算式；map 會把每個產品轉成一個 li */}
        {products.map((product) => (
          // key：與 Vue 的 :key 相同，供 React 比對更新
          <li key={product.id}>{product.title}</li>
        ))}
      </ul>
    );
  }

  ReactDOM.createRoot(document.getElementById("root")).render(<App />);
</script>
```

**步驟四：用 `useEffect` 取得資料**——相當於 Vue 的 `mounted()`。

```html
<script type="text/babel">
  // 多取出 useEffect
  const { useState, useEffect } = React;
  const apiPath = "kentlee406";

  function App() {
    const [products, setProducts] = useState([]);

    // useEffect：處理「副作用」，如發送請求
    useEffect(() => {
      axios
        .get(
          `https://livejs-api.hexschool.io/api/livejs/v1/customer/${apiPath}/products`,
        )
        // 呼叫 setProducts 更新狀態，React 會重新執行 App 並更新畫面
        .then((res) => setProducts(res.data.products))
        .catch((error) => console.error(error));
    }, []); // 依賴陣列為空：只在元件第一次渲染後執行一次
    // 若省略這個 []，每次渲染都會再發請求，造成無限迴圈

    return (
      <ul>
        {products.map((product) => (
          <li key={product.id}>{product.title}</li>
        ))}
      </ul>
    );
  }

  ReactDOM.createRoot(document.getElementById("root")).render(<App />);
</script>
```

> 使用 Vite（`npm create vite@latest -- --template react`）時，把 `App` 放進 `App.jsx` 即可，不需要 Babel CDN。

#### ④ 轉成 Angular（逐步）

> Angular 需透過 CLI 建立專案，無法像 Vue / React 只靠 CDN。

**步驟一：建立專案並啟用 `HttpClient`**

```bash
# 安裝 CLI，建立專案（選用 Standalone 元件）
npm install -g @angular/cli
ng new get-products
cd get-products
```

```ts
// src/app/app.config.ts
import { ApplicationConfig } from "@angular/core";
import { provideHttpClient } from "@angular/common/http";

export const appConfig: ApplicationConfig = {
  // 註冊 HttpClient，之後才能在元件中發送 HTTP 請求
  // （相當於 Vue / React 中載入 axios）
  providers: [provideHttpClient()],
};
```

**步驟二：建立元件並用 `signal` 宣告狀態**

```ts
// src/app/app.component.ts
import { Component, signal } from "@angular/core";

// 資料結構：用 TypeScript 的 interface 描述產品（Vue / React 不強制）
interface Product {
  id: string;
  title: string;
}

// @Component 裝飾器：定義這是一個元件
@Component({
  selector: "app-root", // 對應 index.html 中的 <app-root>
  standalone: true, // 獨立元件，不需 NgModule
  template: ``, // 稍後填入
})
export class AppComponent {
  apiPath = "kentlee406";

  // signal：Angular 的響應式狀態（相當於 Vue 的 data / React 的 useState）
  // 讀取時要加括號：products()；修改用 .set() 或 .update()
  products = signal<Product[]>([]);
}
```

**步驟三：撰寫模板**——用 `@for` 渲染清單。

```ts
@Component({
  selector: "app-root",
  standalone: true,
  // template：畫面模板（也可拆到 .html 檔）
  template: `
    <ul>
      <!-- @for：內建控制流程（Angular 17+），相當於 v-for / map -->
      <!-- track：與 :key / key 相同，用來識別項目（必填） -->
      @for (product of products(); track product.id) {
        <li>{{ product.title }}</li>
      }
    </ul>
  `,
})
export class AppComponent {
  apiPath = "kentlee406";
  products = signal<Product[]>([]);
}
```

**步驟四：在 `ngOnInit()` 取得資料**

```ts
import { Component, OnInit, inject, signal } from "@angular/core";
import { HttpClient } from "@angular/common/http";

interface Product {
  id: string;
  title: string;
}

@Component({
  selector: "app-root",
  standalone: true,
  template: `
    <ul>
      @for (product of products(); track product.id) {
        <li>{{ product.title }}</li>
      }
    </ul>
  `,
})
// implements OnInit：宣告要使用 ngOnInit 生命週期（相當於 Vue 的 mounted）
export class AppComponent implements OnInit {
  // inject()：依賴注入，取得 HttpClient 實例（Angular 的特色）
  private http = inject(HttpClient);
  apiPath = "kentlee406";
  products = signal<Product[]>([]);

  ngOnInit() {
    this.http
      // <{ products: Product[] }>：指定回傳資料的型別
      .get<{ products: Product[] }>(
        `https://livejs-api.hexschool.io/api/livejs/v1/customer/${this.apiPath}/products`,
      )
      // HttpClient 回傳 Observable（RxJS），需 subscribe 才會發送請求
      .subscribe({
        // 成功：用 set() 更新 signal，畫面自動更新
        next: (res) => this.products.set(res.products),
        // 失敗
        error: (err) => console.error(err),
      });
  }
}
```

### 2-2 範例二：todolist（新增 / 刪除待辦）

#### ① 原生 JS（原始碼）

```html
<input type="text" placeholder="請輸入代辦事項" id="txt" />
<button id="add">新增</button>
<ul id="list"></ul>
<script>
  const data = [];
  let nextId = 1;
  const txt = document.getElementById("txt");
  const add = document.getElementById("add");
  const list = document.getElementById("list");
  let listHTML = "";

  function renderList() {
    listHTML = "";
    data.forEach((item) => {
      listHTML += `<li>${item.message} <button class="delete" data-id="${item.id}">刪除</button></li>`;
    });
    list.innerHTML = listHTML;
  }

  // 新增代辦
  add.addEventListener("click", () => {
    const id = nextId++;
    const message = txt.value.trim();
    if (!message) return;
    data.push({ id, message });
    txt.value = "";
    renderList();
  });

  // 刪除代辦（事件委派）
  list.addEventListener("click", (e) => {
    if (e.target.classList.contains("delete")) {
      const id = Number(e.target.dataset.id);
      const index = data.findIndex((item) => item.id === id);
      if (index !== -1) {
        data.splice(index, 1);
        renderList();
      }
    }
  });
</script>
```

**特徵**：要手動「取元素 → 綁事件 → 改資料 → 呼叫 `renderList()` 重繪」，資料與畫面必須自己同步。

```html
<script type="text/babel">
  const { useState } = React;

  function App() {
    const [todos, setTodos] = useState([]);
    const [text, setText] = useState("");
    const [nextId, setNextId] = useState(1);

    // 新增待辦
    const addTodo = () => {
      const message = text.trim(); // 去除前後空白

      setTodos([...todos, { id: nextId, message }]);
      setNextId(nextId + 1); // id 遞增
      setText(""); // 清空輸入框

    // 刪除待辦
    const deleteTodo = (id) => {
      // filter 產生新陣列（不可變更新）
      setTodos(todos.filter((item) => item.id !== id));
    };

    return (
      <div>
        <input
          value={text}
          onChange={(e) => setText(e.target.value)}
          placeholder="請輸入代辦事項"
        />
        <button onClick={addTodo}>新增</button>
        <ul>
          {todos.map((item) => (
            <li key={item.id}>
              {item.message}
              <button onClick={() => deleteTodo(item.id)}>刪除</button>
            </li>
          ))}
        </ul>
      </div>
    );
  }

  ReactDOM.createRoot(document.getElementById("root")).render(<App />);
</script>
```

```ts
import { Component, signal } from "@angular/core";
import { FormsModule } from "@angular/forms";

interface Todo {
  id: number;
  message: string;
}

@Component({
  selector: "app-root",
  standalone: true,
  imports: [FormsModule],
  template: `
    <input [(ngModel)]="text" placeholder="請輸入代辦事項" />
    <button (click)="addTodo()">新增</button>
    <ul>
      @for (item of todos(); track item.id) {
        <li>
          {{ item.message }}
          <button (click)="deleteTodo(item.id)">刪除</button>
        </li>
      }
    </ul>
  `,
})
export class AppComponent {
  todos = signal<Todo[]>([]);
  text = "";
  private nextId = 1;

  // 新增待辦
  addTodo() {
    const message = this.text.trim(); // 去除前後空白
    if (!message) return; // 空白不新增
    // update：以舊值計算新值；用展開運算子產生新陣列
    this.todos.update((list) => [...list, { id: this.nextId++, message }]);
    this.text = ""; // 清空輸入框
  }

  // 刪除待辦
  deleteTodo(id: number) {
    // filter 產生不含該 id 的新陣列
    this.todos.update((list) => list.filter((item) => item.id !== id));
  }
}
```

### 2-3 與原生 JS 的優缺點分析

#### 思維轉換

```
原生 JS（命令式）：  事件發生 → 改資料 → 找 DOM → 改 DOM
框架（宣告式）：     事件發生 → 改資料 → 框架自動更新畫面
```

> **核心差異**：原生 JS 要告訴瀏覽器「**怎麼做**」；框架只需描述「**畫面應該長什麼樣子**」。

#### 原生 JS

| 優點                                        | 缺點                                                    |
| ------------------------------------------- | ------------------------------------------------------- |
| 零依賴、不需建置、打開瀏覽器即可執行        | 資料與畫面需手動同步，漏掉 `renderList()` 就會出錯      |
| 載入最快、體積最小                          | `innerHTML` 拼接字串，整份重繪，且有 **XSS** 風險       |
| 直接學到 DOM、事件、事件委派等底層原理      | 事件委派、`dataset`、型別轉換，寫法繞、可讀性差         |
| 小型頁面最輕巧、沒有框架版本升級問題        | 功能一多（編輯、篩選、分頁）就變成難維護的 DOM 義大利麵 |
| 長期穩定，標準 Web API 不會因框架更替而過時 | 缺乏元件化、路由、狀態管理，團隊協作缺乏統一規範        |

#### Vue 3

| 優點                                                           | 缺點                                            |
| -------------------------------------------------------------- | ----------------------------------------------- |
| 轉換最自然：模板仍是 HTML，原有結構幾乎能直接沿用              | 需載入框架、學習響應式與指令                    |
| 可只用 CDN 漸進導入，不需建置工具                              | 同時有 Options / Composition API，風格易不統一  |
| `v-model` / `v-for` / `@click` 大幅減少樣板碼                  | 響應式有細節陷阱（解構失去響應、`this` 指向等） |
| 響應式 **自動追蹤依賴**，可直接修改資料（`push` 也會更新畫面） | 就業市場與生態規模小於 React                    |
| 學習曲線最平緩，中文資源豐富                                   |                                                 |

#### React

| 優點                                           | 缺點                                                                  |
| ---------------------------------------------- | --------------------------------------------------------------------- |
| 一切都是 JS（JSX），邏輯與畫面可高度組合與抽象 | 純 CDN 不便，實務幾乎一定要 Vite / Next.js 等工具                     |
| 生態最大，職缺多，且能延伸到 React Native      | 需要習慣**不可變更新**（`push` 無效）、Hooks 規則、依賴陣列與閉包陷阱 |
| 嚴格單向資料流，資料流向容易追蹤               | 輸入框需寫受控元件（`value` + `onChange`），比 `v-model` 冗長         |
| 彈性最高                                       | 只管 UI，路由、狀態管理、表單都要自行選擇                             |

#### Angular

| 優點                                               | 缺點                                                                   |
| -------------------------------------------------- | ---------------------------------------------------------------------- |
| 內建一切（路由、表單、HTTP、DI），不用煩惱選型     | 一個簡單 todolist 也需 CLI、TypeScript、裝飾器、元件檔案，**樣板碼多** |
| 強型別（TypeScript）提早抓錯，適合長期維護大型專案 | 學習曲線最陡（DI、RxJS、Signals、模組概念）                            |
| 規範嚴格，團隊風格一致                             | 不適合小型頁面，不能漸進導入                                           |

#### 總結比較

| 考量面向           | 原生 JS            | Vue 3        | React    | Angular      |
| ------------------ | ------------------ | ------------ | -------- | ------------ |
| 上手難度           | 最低（但維護最累） | ⭐ 低        | 中       | 高           |
| 開發效率（中大型） | 低                 | 高           | 高       | 高（初期慢） |
| 小型專案適用       | ⭐ 最適合          | 適合         | 稍重     | 過重         |
| 大型專案適用       | 不適合             | 適合         | 適合     | ⭐ 最適合    |
| 是否需建置工具     | 否                 | 否（可 CDN） | 通常需要 | 必須         |
| 生態規模           | —                  | 大           | ⭐ 最大  | 大           |
| 型別安全           | 無                 | 可選 TS      | 可選 TS  | ⭐ 內建      |

#### 結論

1. **框架的價值不是「少寫幾行」，而是「不用再手動管 DOM」**，把心力放在資料與邏輯上。
2. 專案規模越小、互動越少，原生 JS 越划算；專案規模越大、互動越多，框架的優勢越明顯。
3. 三大框架解決的是同一個問題（讓資料驅動畫面），差別在於：
   - **Vue**：語法最貼近 HTML，上手最快，漸進式導入
   - **React**：用 JS 組合一切，彈性與生態最大
   - **Angular**：全包式與強規範，適合大型企業
4. 學習路徑建議：**先學原生 JS 理解 DOM → 再學 Vue（平緩）→ 理解元件化與響應式後，轉換到 React / Angular 的成本會很低**。
